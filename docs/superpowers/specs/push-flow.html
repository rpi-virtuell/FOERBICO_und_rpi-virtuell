Was nach einem Push auf main passiert

Der Ablauf des neuen Sync-Skripts: vom Merge bis zum Exit-Code. Das Relay entscheidet, ob publiziert wird — nicht die Git-Historie.

Drei mögliche Ausgänge je Beitrag

publiziert

Die Tags weichen vom Relay-Stand ab, und mindestens MIN_RELAY_ACKS (2) Relays haben das signierte Event bestätigt.

unchanged

Das Relay trägt bereits genau diese Tags. Es wird nichts gesendet — kein neuer created_at, keine Event-ID, kein Rauschen für Abonnent*innen.

Fehler

Spezifikationsverletzung, unerreichbares Relay oder zu wenige Bestätigungen. Das Event wird nicht publiziert, der Job endet rot.

Warum der Git-Diff nur ein Vorfilter ist

  • Der Diff bestimmt nur, welche Beiträge angesehen werden — er entscheidet nie, ob publiziert wird. Das tut allein der Vergleich mit dem Relay.
  • Deshalb liefert ein Lauf mit --all dasselbe Ergebnis wie ein Lauf mit Diff: Squash-Merges, Force-Pushes und manuelle Re-Runs können nichts verschlucken.
  • Die Idempotenz-Abfrage gibt immer -a <unser-pubkey> mit. Ohne das könnte ein fremdes Event zum selben Slug als „schon publiziert“ durchgehen.
  • Ein unerreichbares Relay ist ein harter Fehler — nicht „sicherheitshalber publizieren“ (Spam) und nicht „unverändert annehmen“ (stiller Verlust).
